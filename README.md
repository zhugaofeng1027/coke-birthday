# 生日小厨房

一个手机优先的实时厨房生日游戏。基于 Phaser Arcade Physics 实现主厨移动与台面碰撞，使用原创 Canvas 美术，不使用原作游戏素材。

主厨采用用户提供的卡通形象，透明 PNG 位于 `src/assets/birthday-chef.png`；场景绘制保留原有移动动画与脚底定位。
六关完成后，结尾主厨通过星光变身动画换成 `src/assets/birthday-chef-party.png` 的生日帽形象；吹蜡烛和回看礼物时保留新形象，系统启用减少动态效果时直接切换。

六间主题厨房依次解锁六份生日礼物。每关需要亲自取材、切配、煮制或烘烤、等待熟成、装盘，按该厨房的线索完成出餐。礼物名称只在生日便笺揭晓后出现。

## 开场故事

首次进入会播放“今晚，只为你营业”的四幕开场：小店亮灯、小助手的邀请信、六道日常菜单、推门进入厨房。约 14 秒后抵达门前，等待点击“开门，今天我主厨”；可随时暂停、跳过、开关音乐，也可逐幕手动前进。系统启用减少动态效果时不自动播放，手动阅读即可。

开场支持手机竖屏，进入厨房后才提示横屏。同一标签页刷新不重复开场；再次来访提供“继续”与重看入口，不改动关卡存档。设置里的“重看开场故事”可随时回看，返回时保留当前料理和位置。开发环境可用 `?intro=1` 预览完整开场，不清除进度；调试关卡默认跳过开场。

六关结束后，小助手先邀请主厨成为今天的主角，再衔接生日帽变身和许愿。开场仅展示料理和日常场景，不提前揭晓礼物。

## 六间厨房

| 厨房 | 料理 | 特别机关 | 礼物 |
| --- | --- | --- | --- |
| 果园甜品站 | 双果酱烤吐司 | 根据形状与颜色选材，同锅熬出爱心果酱，抹上烤吐司 | 果汁软糖 |
| 口袋便当铺 | 出门前的爱心便当 | 饭菜装盒后盖盖、套绑带、贴封签，亲手交出便当 | Chiikawa 挂件 |
| 深夜卤味档 | 深夜慢卤牛肉 | 逐味取香料装袋，亲手下锅成卤汤，再下牛肉 | 卤货零食大礼盒 |
| 时光食堂 | 照片里的双人餐 | 对照旧餐照做菜，上桌后取景、对焦、拍照，显影留念 | 拍立得相纸 |
| 月光香草厨房 | 薄荷热茶与烤面包 | 端热茶靠近玻璃显字，按线索把茶和面包送到灯旁、花下 | 香薰 |
| 花园餐厅 | 生日主厨拼盘 | 按前奏、主调、尾声摆盘，点亮花园 | 古驰香水礼盒 |

特别工作台提供关卡线索与机关操作，顶部笔记本可随时重读线索。只有最终拼盘仍使用餐序表单；前五关的机关直接融入做菜动作。厨房仅使用可食用的薄荷与普通食材，香薰和香水仅作为揭晓的礼物。

每关限时挑战：依次为 4:00、5:00、5:30、5:00、4:00、5:00。订单从开局按固定间隔持续进入队列，不等待出餐：各关间隔为 40、45、50、45、40、45 秒，每单分别限时 110、130、150、130、110、130 秒。顶部横向队列同时展示多张订单、独立倒计时和耐心进度条，只显示食物，不提供切配、烹饪方式或时长。

每次出餐核销最早的有效订单并加 100 分；订单超时移出队列、每单扣 30 分，分数可以为负。超时不清空食物、打包/照片进度或机关线索。没有有效订单时可以继续备菜，送餐不会消耗食物或提前生成订单。累计 200 分才通关、收到生日便笺。每份料理需完成对应的打包、拍照或摆盘；已配好的卤汤与已显字的玻璃保留。整关剩余 30 秒时计时器变红，到时冻结厨房并提供重试，未达标不解锁礼物。

各厨房的实际机关：

- 果园：切好的草莓与葡萄同锅熬煮，只有正确组合才冒爱心；猕猴桃或重复水果不会通过。配错后可把新的切好水果加入锅中，替换不合适的那份，不影响已烤好的吐司。果酱与烤吐司放到同一餐盘时自动抹酱，完成配方。
- 便当：煮米饭、烤鸡肉、切西兰花，按任意顺序装进普通餐盘，端到右下角便当打包台。饭菜自动装盒，再依次将盒盖、绑带和爱心封签拖到便当上，也可以点击对应材料完成同一步操作。每一步都直接改变盒子的外观；乱序或拖到盒外不会丢失材料，关闭再打开保留进度。封好后点击“带上便当”，亲手送至左侧取餐口才算完成。
- 卤味：下方四罐香料可逐味取出，送到右下角卤料袋。星星、木筒、叶子分别对应八角、桂皮、香叶，辣椒和重复香料不会通过。配错可空手取回最后一味，再放回原罐。配齐后再操作一次拿起袋子，亲手放进煮锅才会成为卤汤；之后切肉、卤牛肉和胡萝卜，装盘送至左侧取餐口。
- 时光：右下角旧餐照提供菜品线索。煮番茄热汤、烤吐司、切蘑菇，在普通装盘台装成一盘，不要求左右顺序。端到左侧双人餐桌后进入相机，可拖动画面或使用方向按钮取景，用焦点滑杆调整清晰度。两套餐具入镜且焦点清晰时拍照，照片逐渐显影；可以反复重拍，满意后留下这张才完成这一单。关闭相机不会丢失晚餐，再操作餐桌或相片台即可继续。
- 月光：必须端着已煮好的薄荷茶，在右下角玻璃前连续停留两秒，锅中或远处的茶不会显字。根据“热茶留在灯旁，面包放在花下”，将茶留在左侧灯旁，把装盘的烤面包送到右下花下餐位。也可先同盘装好，餐位会取走对应那份；放错位置保留手中料理。两处送齐后自动出餐。

时光食堂当前使用原创 Canvas 双人餐桌与餐照，尚未接入你们的真实照片；最终餐序是游戏叙事，不对应任何具体香水的实际香调。

## 操作

- 手机横屏：宽厨房铺满屏幕，工作台按横向空间重新排布，厨师同步放大。摇杆悬浮在左下角，取放和切配按钮在右下角；订单与手持物品收在上方，整屏无需上下滚动。顶部可看倒计时、得分、提示、礼物簿和设置。便笺与礼物采用双栏，长文独立滚动，标题、关闭和主要按钮保持可见，入场不自动弹键盘。
- 手机竖屏时提示旋转，并暂停移动和烹饪计时；转回横屏继续同一份料理，不会重开关卡。支持全屏的浏览器可使用顶部全屏按钮。
- 电脑：方向键或 WASD 移动，E 取放与操作，按住空格切配，也支持鼠标操作摇杆和按钮。
- 一次只能拿一份食材或一个餐盘，靠近对应工作台才能操作。
- 盘子架在左侧，切配台和煮锅在中间，烤箱在右侧，特别工作台在右下角。第二、三关取餐口与第四关双人餐桌在左侧，其余关卡在下方；第三关下方右侧是四罐香料。
- 食物切好后才能烹饪；吐司不需要切配。锅和烤箱自动计时，可以并行备菜。
- 先把空盘放在装盘台，再逐个加入处理好的食材；也可以直接用端着的盘子从锅和烤箱盛取熟食。
- 食物熟了不会烧焦。拿错食材可以送到左下方回收桶，或重新制作当前菜品。
- 阅读线索、设置等弹窗，旋转至竖屏或切到其他应用时暂停倒计时和烹饪。打包、相机/照片、最终摆盘属于料理操作，打开期间厨师停止移动，但倒计时与锅、烤箱继续运行。

## 运行

```bash
npm install
npm run dev
```

浏览器访问终端显示的地址。右上角二维码可在同一 Wi-Fi 下用手机体验，电脑需要保持运行。

生日蛋糕可用麦克风吹灭蜡烛：点击「用气息吹」并允许麦克风权限，等提示后对着麦克风吹气。手机需要用 HTTPS 地址打开；电脑开发时可用 localhost。声音只在设备上实时检测，不录音、不上传；不授权或从局域网 HTTP 地址打开时，也可选择「点按吹灭」。

电脑调试可点击顶部手机图标，或打开 `http://localhost:5173/?preview=phone`。预览器提供固定手机/平板横屏尺寸，会自动缩放以适应电脑窗口；可直接使用方向键/WASD、E、空格游玩。切换预览尺寸不重开料理。普通电脑窗口即使很窄也不再强制显示旋转提示；`?layout=desktop` 可显式使用电脑布局。

从设置中的“关卡调试”进入，或给游戏网址加 `?debug=1` 直接进入调试。可直达第 1–6 关、开场动画、隐藏礼物或吹蜡烛，手机横屏预览也支持。刷新保留当前调试环节，并从头重试；调试不会写入正式存档。通过虫形图标选择“正式闯关”可恢复原来的进度和关卡锁定。`?debug=1&chapter=4` 可直接调试第四关。分享二维码不会携带调试参数。

六关都使用升级后的厨师动作、工位反馈和分层厨房布景，各自保留主题与解谜玩法。点顶部喇叭打开音效和原创 BGM；订单剩 15 秒时提速，营业剩 20 秒时进入冲刺节拍。

开发环境用 `?preview=phone&debug=1&chapter=2&kitchen-polish=after` 打开第二关的对照小样，追加 `&bgm-audition=1` 可试听短倒计时。预置食材和短倒计时只在小样中使用。

```bash
npm test
npm run build
npm run test:e2e
```

端到端测试需要先启动开发服务器并执行 `npx playwright install chromium` 安装测试浏览器。测试包括真实按键移动、碰撞、持续切配、实际等待烹饪、六关机关、触屏摇杆与礼物流程。六关完整流程在桌面和手机运行，其他尺寸也覆盖首关和横屏布局。

## 修改生日内容

右上角设置可编辑称呼、署名、六份礼物的谜面、揭晓后的留言和结尾。保存仅作用于当前浏览器。

要让手机或正式站点使用修改后的内容，在设置中点击“导出当前表单”，将下载的 `config.json` 替换 `public/config.json`，重新构建部署。也可以直接修改这个源文件。配置和游戏进度分别保存在本机 localStorage 中，重置进度不会清除文案。

默认礼物顺序为：果汁软糖、Chiikawa 挂件、卤货零食大礼盒、拍立得相纸、香薰、古驰香水礼盒。实际礼物请按 01–06 编号包装。

## 部署与二维码

`npm run build` 生成 `dist/`，可发布到支持静态文件的 HTTPS 网站。必须同时部署 `dist/config.json`。二维码使用当前域名；部署后再制作正式二维码，不能把 localhost 或局域网二维码用于异地访问。

### GitHub Pages

1. 源码保存在 `main`。用 `npm ci` 安装依赖，运行 `npm test` 和 `npm run build`。
2. 从 `gh-pages` 分支的根目录发布。在仓库的 `Settings → Pages` 中，确认 `Source` 为 `Deploy from a branch`、分支为 `gh-pages`、目录为 `/ (root)`。
3. 更新线上版本时，把 `dist/` 的内容发布到 `gh-pages` 根目录，保留 `.nojekyll`，再推送该分支。只推送 `main` 不会更新线上版本。
4. 部署成功后，在 `Settings → Pages` 查看正式 HTTPS 地址。用手机浏览器直接打开该地址，吹蜡烛时允许麦克风访问。要直接测试吹蜡烛，可给正式网址加 `?debug=1&candle=1`。

固定扫码图在 `public/play-qr.png`，指向正式首页。只要正式网址不变，每次更新都可以继续用同一张图。

Pages 站点公开可访问。发布前确认生日文案、图片和客户端礼物配置都可以公开；知道网址的人无需登录就能访问。

本项目不包含用户注册、联网对战、云端同步和付费服务。音乐通过 Web Audio 合成，默认静音，点击顶部音量按钮开始。新厨房玩法使用独立的 v2 关卡存档，不会删除旧版解谜存档或自定义生日文案。

礼物的答案保存在客户端，适用于私人生日惊喜，不用于需要防作弊或保密的场景。
